1. Core Gameplay Loop

Episode Creation & Configuration Ready

Requirement: Host creates an Episode with configurable rounds, questions, categories, and videos.

  • POST /episodes/create JWT — Create episode with Title, Description, ThemeConfig (JSONB), SponsorConfig (JSONB)
  • POST /episodes/get JWT — Returns full episode tree: episode → rounds → questions (nested JSON)
  • POST /episodes/update JWT — Partial update (only send fields you want to change)
  • POST /episodes/list JWT — List all episodes
  • POST /episodes/delete JWT — Cascade deletes rounds + questions
Front-end note: ThemeConfig and SponsorConfig are freeform JSONB — you can store any structure (colors, fonts, logos). Backend stores and returns it as-is.

Round Configuration Ready

Requirement: Configurable rounds with timer, point pool options, timed bonus tiers, negative scoring, and scoring mode.

  • POST /rounds/create JWT — Set TimerSeconds, PointPoolOptions (e.g. [2,4,6,8]), TimedBonusTiers, NegativeScoring, ScoringMode
  • POST /rounds/update JWT — Update any round config
  • POST /rounds/delete JWT — Delete round + cascade questions
Scoring modes: "point_pool" | "timed_only" | "both". Halftime/Final rounds = just rounds with ScoringMode: "timed_only".

Question Management + Video Upload Ready

Requirement: Questions with categories, MC options, correct answer, per-question timer override, and question/answer videos.

  • POST /questions/create JWT — QuestionText, CorrectAnswer, Options (array), Category, QuestionType, TimerSecondsOverride, ScoringModeOverride
  • POST /questions/update JWT — Partial update
  • POST /questions/delete JWT
  • POST /questions/move JWT — Move a question between rounds
  • POST /questions/upload-video JWT — Upload question or answer video (Base64 → stored on server). Send VideoType: "question" or "answer"
Question types: "multiple_choice" | "true_false" | "open_ended". For MC, send Options: ["A", "B", "C", "D"].
Timer override: If TimerSecondsOverride is set, it overrides the round's TimerSeconds for that question only.

2. Game Session Lifecycle

Session Creation + Room Code + QR Ready

Requirement: Host starts a Game Session → gets a Room Code. Players scan a QR code to join.

  • POST /sessions/create JWT — Creates session, returns 6-character RoomCode and QRData (trivitime://join/{RoomCode})
  • POST /sessions/status Public — Get session state + team count (for lobby screen)
QR code: Backend returns QRData: "trivitime://join/EMW3PN". Front-end generates the QR image from this string. Room codes use ambiguity-free charset (no I/O/0/1).

Session State Machine Ready

Requirement: Session goes through lobby → active → completed. Host controls pacing.

  • POST /sessions/start JWT — lobby → active. Sets Round 1, Question 1, starts timer
  • POST /sessions/next-question JWT — Advances to next question. Auto-advances rounds. Auto-completes session when all questions done. Resets QuestionStartedAt
  • POST /sessions/end JWT — Force-end → completed
Pacing is host-driven: The host decides when to advance. Front-end should show a "Next Question" button that calls /sessions/next-question. Between questions, the host can talk, show leaderboard, play videos, etc.

Host Link (Shareable Game Link) Ready

Requirement: Generate a shareable "Game Host Link" (24h expiry) so someone else can host without the admin password.

  • POST /host-link/generate JWT — Returns a URL-safe token + RoomCode + expiry timestamp. Creates a session in lobby state.
  • POST /host-link/validate Public — Validate token → returns session info. Host can now control the session.
Flow: Admin generates link → shares URL like https://trivitime.app/host?token=abc123 → Host opens link → front-end calls /host-link/validate → gets session → can start/advance/end.

3. Player Experience

Join Session + Team Creation + Avatar Ready

Requirement: Players scan QR → enter Room Code → set Team Name. No account needed. Optional avatar upload.

  • POST /sessions/join Public — Send RoomCode, TeamName, optional AvatarBase64. Returns IDTeam (save this in localStorage — it's the team's identity for the rest of the game)
Important: The returned IDTeam is needed for all subsequent player actions (submit, point-pool, current-question). Store it client-side.
Validation: Duplicate team names in the same session are rejected (400). Cannot join after session starts (400).

View Current Question + Timer + Wagers Ready

Requirement: Players see the current question, timer, and pick a point wager.

  • POST /sessions/current-question Public — Returns: QuestionText, Options, Category, QuestionType, TimerSeconds, AvailableWagers (remaining point values), QuestionStartedAt
Timer: Server returns QuestionStartedAt (UTC timestamp) + TimerSeconds. Front-end calculates countdown:
remaining = TimerSeconds - ((Date.now() / 1000) - QuestionStartedAt)

Wagers: AvailableWagers shows remaining values (e.g. [2, 4, 6] if 8 was already used). Display these as selectable buttons/chips.

Answer Submission + Timer Enforcement Ready

Requirement: Teams pick a point wager and submit an answer. Timer enforced. Late submissions saved but don't count.

  • POST /sessions/submit Public — Send IDTeam, IDQuestion, AnswerText, WageredPoints. Returns WasOnTime, SubmissionSeconds, TimedBonusAwarded
Key behaviors:
• Late answers are saved with WasOnTime: false — no error, they just score 0
• Wager must be one of AvailableWagers — invalid wager returns 400
• Duplicate submission for the same question returns 400
• Timed bonus is calculated server-side from the round's TimedBonusTiers config

Point Pool Tracking Ready

Requirement: Each team has a pool of wager values per round. Once a value is used, it's consumed.

  • POST /sessions/point-pool Public — Returns AvailableValues (remaining wager options for the current round)
Example flow: Round starts with [2, 4, 6, 8]. Team wagers 8 on Q1 → remaining: [2, 4, 6]. Team wagers 4 on Q2 → remaining: [2, 6]. Handles duplicate values (e.g. [7, 7, 8, 8] — wagering 7 removes one instance).

4. Scoring & Leaderboard

Auto-Grading + Score Calculation Ready

Requirement: Host marks answers. Score = wager ± negative + timed bonus. Leaderboard updates in real-time.

  • POST /sessions/grade JWT — Auto-grades all responses (case-insensitive match against CorrectAnswer). Calculates scores. Updates leaderboard rankings.
Condition Score
✅ Correct + ⏱ On time WageredPoints + TimedBonusAwarded
✅ Correct + ⏰ Late 0
❌ Wrong + ⏱ On time (NegativeScoring ON) -WageredPoints
❌ Wrong + ⏱ On time (NegativeScoring OFF) 0
❌ Wrong + ⏰ Late 0
⚠️ Current implementation: Grading is auto (exact match). If you need manual host override for open-ended questions, that's a future enhancement — currently auto-grade works best for MC and True/False.

Leaderboard Ready

Requirement: Ranked leaderboard shown at host's discretion. Shows total + per-round scores.

  • POST /sessions/leaderboard Public — Returns ranked entries: TeamName, AvatarBlobPath, TotalScore, RoundScore, Rank
Usage: Call after grading to display results. Can also be polled to show live standings. RoundScore is the score for the current round only; TotalScore is cumulative.

View All Responses Ready

Requirement: Host can see all team responses for a question.

  • POST /sessions/responses JWT — Returns all submissions. Optional filter by IDQuestion. Shows AnswerText, WageredPoints, IsCorrect, WasOnTime, SubmissionSeconds

5. Team Management

List & Kick Teams Ready

Requirement: Host can see teams in the lobby and remove disruptive teams.

  • POST /sessions/teams Public — List all teams: TeamName, AvatarBlobPath, JoinedAt
  • POST /sessions/kick JWT — Remove a team (cascades: removes responses, point pools, scores)

6. Authentication

Master Login (JWT) Ready

Requirement: Single admin user, seeded from environment. No signup. JWT for session management.

  • POST /auth/login Public — Send Email + Password → returns access_token (JWT, 24h expiry)
Usage: Store the token. Add to all 🔒 JWT endpoints as: Authorization: Bearer <token>

7. What's NOT Yet Implemented

Manual Answer Grading Override Future

For open-ended questions, host may want to manually mark an answer correct/incorrect. Currently auto-grading only (exact text match). Can be added as POST /responses/mark if needed.

Real-Time Updates (WebSocket/SSE) Future

Currently all data is fetched via polling (call endpoints on interval). WebSocket/SSE for live push updates (new team joined, question advanced, leaderboard changed) can be added if polling latency is an issue.

Session Pause/Resume Future

The requirements mention a "paused" state. Currently: lobby → active → completed. A pause state can be added easily when needed.
